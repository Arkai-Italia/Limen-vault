29: ## 2. Le Sei Correzioni e Specifiche Operative della FASE 5
30: 
31: ### 1. Punto b) — Riferimenti Errati, Prima Misurare nel Registro
32: - **Correzione di attribuzione**: In `search.rs` non viene calcolato alcun vettore; le righe 440–510 indicizzate in precedenza gestiscono il frontmatter. Il calcolo della similarità semantica avviene interamente in `apps/desktop/src-tauri/src/embeddings.rs` (funzioni `rank_document_semantic` e `cosine_similarity`).
33: - **Misurazione preliminare nel log**: Prima di intraprendere qualunque ottimizzazione del codice di ricerca, viene aggiunta nel registro `ask_timing.log` la divisione puntuale del tempo di ricerca nelle sue 4 componenti effettive:
34:   1. **Ricerca per parole (`search_words_ms`)**: tempo della ricerca lessicale BM25 in `search::search_vault_filtered`;
35:   2. **Similarità semantica (`search_sem_ms`)**: tempo del calcolo vettoriale in `embeddings::rank_document_semantic` su tutti i passaggi del catalogo;
36:   3. **Fusione e ordinamento (`search_fuse_ms`)**: tempo di unione, normalizzazione min-max e ranking RRF in `embeddings.rs`;
37:   4. **Filtro di ammissibilità (`search_admit_ms`)**: tempo del filtro Punto E (`filter_candidates_punto_e` in `ai.rs`).
38: - **Regola di cautela vincolante**: Si ottimizzerà esclusivamente la componente che le misurazioni di Cesare indicheranno come collo di bottiglia, e solo a condizione di **non alterare in alcun modo i risultati** (stesse identiche fonti per BNXT, ARKAI e SCENA verificate sulla porta del servizio dell'app).

40: ### 2. Punto c) — Fonti Mostrate Subito
41: - Non appena la fase locale di `preview` è completata (~1–2 s), l'interfaccia mostra immediatamente nella scheda "Chiedi" l'elenco dei documenti consultati a supporto della domanda (con titolo pulito e leggibile tramite `cleanTitle`), con l'etichetta *"Fonti consultate dal Vault per questa domanda (in attesa di risposta…)"*.
42: - Mentre il testo in streaming si compone, l'utente può già visualizzare l'elenco delle fonti estratte.
43: - Al termine dello streaming, i documenti effettivamente citati dal modello vengono evidenziati con il badge *"CITATA"* e compare l'etichetta trasparente definitiva:  
44:   **"Basata su N documenti citati tra M consultati"**.

46: ### 3. Controllo di Integrità Post-Risposta (`verify_post`)
47: - Il controllo `verify_post` resta tassativo e obbligatorio prima di considerare valida la sessione.
48: - Con lo streaming, il testo è già apparso progressivamente a schermo: se `verify_post` fallisce (poiché uno dei documenti o passaggi è mutato su disco durante i secondi della chiamata), **il testo mostrato viene immediatamente sostituito da un avviso chiaro**:  
49:   > *"Un documento è cambiato durante la generazione: la risposta è stata annullata, riprova"*
50: - Nessuna citazione viene mostrata (`citations: []`).
51: - Un test unitario dedicato convalidi questa sostituzione protettiva.
52: 
53: ### 4. Pulizia Durante lo Streaming (`sanitize_answer_prose`)
54: - Frammenti successivi dello stream SSE possono spezzare sigle o marcatori (es. `"[S"` nel frammento 1 e `"1]"` nel frammento 2, oppure `"*"` e `"*BNXT**"`).
55: - Per evitare che frammenti grezzi appaiano temporaneamente all'utente, viene implementato `StreamProseSanitizer` dotato di **sliding tail buffer**:
56:   - Trattiene la porzione terminale ambigua (fino a 10 caratteri) se coincide con un prefisso di sigla (`[`, `[S`, `(`) o di marcatore (`*`, `**`);
57:   - Emette verso la UI solo il testo certo e già pulito tramite `sanitize_answer_prose`;
58:   - A fine stream svuota l'eventuale residuo garantendo la totale assenza di sigle grezze o asterischi markdown.
59: - Test dedicati:
60:   - Frammenti spezzati `"[S"` + `"1]"` $\rightarrow$ non mostrano mai `[S1]`;
61:   - Frammenti spezzati `"**"` + `"BNXT**"` $\rightarrow$ non mostrano mai asterischi.
62: 
63: ### 5. Risposte Interrotte
64: - Se lo streaming si interrompe (errore di rete, chiusura connessione, annullamento dell'utente o limite di token raggiunto prima della chiusura JSON):
65:   - Il testo parziale generato fino a quel momento resta visibile all'utente, accompagnato da un avviso esplicito e semplice di interruzione;
66:   - **Zero citazioni**: nessuna fonte viene contrassegnata come citata (`citations: []`) per prevenire attribuzioni parziali o non verificate.
67: - Questa regola viene formalmente sancita nel rapporto di implementazione.
68: 
69: ### 6. Schema Responses API Rigoroso
70: - L'app utilizza e mantiene la Responses API di OpenAI (`text.format` JSON schema):
71: ```json
72: {
73:   "model": "gpt-4o",
74:   "store": false,
75:   "max_output_tokens": 1500,
76:   "input": [
77:     { "role": "system", "content": "..." },
78:     { "role": "user", "content": "..." }
79:   ],
80:   "text": {
81:     "format": {
82:       "type": "json_schema",
83:       "name": "vault_answer",
84:       "strict": true,
85:       "schema": {
86:         "type": "object",
87:         "properties": {
88:           "answer": { "type": "string" },
89:           "citation_ids": {
90:             "type": "array",
91:             "items": {
92:               "type": "string",
93:               "enum": ["S1", "S2", "S3", "S4", "S5", "S6", "S7", "S8"]
94:             }
95:           }
96:         },
97:         "required": ["answer", "citation_ids"],
98:         "additionalProperties": false
99:       }
100:     }
101:   }
102: }
103: ```
104: - Lo streaming SSE consuma esattamente lo stesso schema, preservando i controlli di `parse_response` (stato presente, esattamente un output_text, citazioni validate, conteggio token input, output e reasoning).
