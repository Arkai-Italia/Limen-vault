4. SINTESI TECNICA DELLA VERIFICA SUI 7 CASI REALI
--------------------------------------------------------------------------------
- Caso 1 (Immagine PNG): Tesseract 5.4.0 Windows nativo avviato come processo child con CREATE_NO_WINDOW; estrazione completata con esito 0 e riconoscimento dei lemmi italiani ed accenti.
- Caso 2 (PDF vettoriale puro): PDFium accede alla memoria e legge i glifi vettoriali digitali; nessun passaggio OCR superfluo; is_partial=false; warnings=[].
- Caso 3 (PDF scansionato puro): PDFium esegue rasterizzazione della pagina a 150 DPI in memoria BGRA, codifica BMP standard in RAM, passa l'immagine a Tesseract OCR; testo estratto con successo; is_partial=false.
- Caso 4 (PDF misto): PDFium estrae i glifi vettoriali, rasterizza la porzione grafica, esegue OCR su quest'ultima e unisce i risultati con algoritmo di deduplicazione; il testo vettoriale compare esattamente 1 volta senza alcuna duplicazione.
- Caso 5 (DOCX degradato): Il motore di estrazione apre il package zip Office, estrae il testo XML principale (LIMEN-DOCX-GUASTO-TESTO-XML) e intercetta il guasto dell'immagine embedded senza crash né panico, contrassegnando is_partial=true e registrando il warning specifico nell'array warnings.
- Caso 6 (RTF): Il parser RTF nativo decodifica l'albero sintattico RTF gestendo font table, color table e caratteri accentati Windows ANSI (\'e8, \'e0, ecc.); testo estratto perfettamente.
- Caso 7 (DOC legacy): Compound File Binary OLE2 aperto direttamente dal parser Rust cfb; individuato lo stream /WordDocument; decodificati i run testuali; testo estratto con successo e accenti preservati.
